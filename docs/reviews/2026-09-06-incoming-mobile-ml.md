Проверка в копии `a948d45` с **ровно этими тремя входящими файлами**:

на `3006492`. При переносе надо обновить его на **точный код коллеги**, а не

на его экране, причины выбора режима — в API. Это надо учитывать при показе
объяснимости, но автоматически возвращать прежние текстовые блоки не нужно.

**Вывод:** кандидат на ближайший ограниченный merge с сохранением визуала автора.
Новые backend-решения для этих коммитов не требуются.

### Воспроизведённая несовместимость kitchen/completion

Во временной копии `13a70c5` прошли **32 теста** kitchen, цены и ready-food pairs.
Это подтверждает поведение **его** контрактов, не совместимость с нашей сборкой.

На его же fixture из `tests/test_kitchen_contract.py`:

1. Чек с творогом и десятью яйцами даёт **10 XP за покупку**, без задания.
2. Отдельный `POST /api/v1/events/recipes/completed` для сырников без meal-plan
   увеличивает итог до **30 XP**.
3. После готовки кладовка становится пустой: удалён весь баланс ингредиентов,
   включая все десять яиц, без расчёта реально использованного количества.

У нас иначе: покупка без задания даёт 0 XP, награда связана с серверным offer,
планом и подходящей покупкой, действует ограничение на покупочный день;
готовка не удаляет упаковки целиком. Прежние constants уже были в основе
ML-ветки — новые коммиты не «сломали» нашу рабочую сборку. Но новый completion
написан под эту старую основу и не должен стать параллельным путём выдачи XP.

Есть и расхождение recipe-content:

- `pasta_tomatoes` отсутствует в новом API деталей, хотя это основной мобильный
  рецепт нашей версии.
- Для `chicken_soup` там указаны только курица и морковь; наш согласованный
  состав включает также обязательный лук.
- Для болоньезе там базилик включён в обязательный набор completion;
  у нас он необязательный.

Поэтому справочный `GET /recipes/{id}` можно рассматривать отдельно, только
после выравнивания каталога и шагов. Перенос нового события готовки, списания
всей кладовки или замена наших endpoint-клиентов целиком не являются
механическим заполнением пробела.

Ни новых результатов конечного meal-eval, ни LLM-прогона среди этих изменений
нет. Это не утверждение, что коллега ничего не запускает локально.

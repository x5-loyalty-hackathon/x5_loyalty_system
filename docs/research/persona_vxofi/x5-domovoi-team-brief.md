# Current idea: X5 Домовой × recipe-first «Спасённая корзина»

> **Статус:** current state, согласованный командой 2026-09-03. Это рабочие
> решения для PoC и последующей проверки, а не измеренные результаты.

## Формулировка

После покупки recommender предлагает рецепты на основе чека и предпочтений.
Пользователь может выбрать знакомое блюдо, повторить сохранённое или открыть
новый рецепт с новыми продуктами. Рецепты сортируются по релевантности и числу
недостающих ингредиентов: при сопоставимой релевантности меньше missing items
показываются выше.

При сборе рецепта для недостающего ингредиента можно выбрать уценённый SKU в
достижимом радиусе. Если уценки нет, предлагается full-price вариант; если нет
подходящего товара вообще, candidate исключается или рецепт изменяется.
Собранный список можно отправить в стандартную доставку либо сохранить к
следующему визиту. Отдельной брони rescue-позиции и денежной награды нет.

После следующего чека продукты приезжают в дом Домового, рецепт сохраняется, а
личная история и статистика обновляются.

```text
чек + история + предпочтения
→ знакомые и discovery-рецепты
→ сортировка по relevance и missing count
→ markdown/full-price выбор внутри ингредиентов
→ доставка ИЛИ следующий визит
→ новый чек
→ рецепт, Домовой и личный progress
```

## Зафиксированные командой ответы

| Вопрос | Ответ |
|---|---|
| Основной PoC | `V3 + V4`: recipe basket + Домовой |
| География | достижимый радиус |
| Размер | не фиксирован; меньше missing items выше |
| Fulfillment | доставка либо следующий визит |
| Бронь rescue | нет |
| Дополнительная reward | нет |
| Категории | фрукты, овощи, молочные продукты, мясо и другие short-life staples базовых блюд |
| Cross-sell | только ингредиенты выбранного рецепта, без out-of-recipe рекомендаций |
| ЦА | домохозяйства, покупающие продукты для приготовления блюд |
| Gambling-like слой | пока исключён |
| Рейтинг | только личная статистика |
| Нет markdown | full-price fallback; при отсутствии аналога — отмена candidate/сборки |
| Частота показа | recipe feed ежедневно, push не ежедневно |

## Это больше не заранее собранный физический бокс

Текущая «Спасённая корзина» — цифровая корзина ингредиентов выбранного рецепта.
Магазин не собирает отдельный лот, товар не резервируется, no-show отсутствует.

Уценка становится опцией на уровне ингредиента:

| Ингредиент | Возможное состояние |
|---|---|
| уже был в чеке | `куплено` |
| подтверждён пользователем | `есть дома` |
| найден short-life SKU рядом | `уценка` |
| уценки нет | `full-price` |
| аналога нет | `недоступно`, заменить или убрать рецепт |

Для следующего визита наличие best-effort: пользователь предупреждён, что
товар не забронирован. Для доставки действуют стандартные checkout, оплата,
замены и отмена. Production-интеграция с доставкой в PoC только симулируется.

## Почему это не рекламный рецепт

Новый продукт или бренд допустимы, если они появились из персонального
recommendation context, а не из скрытого коммерческого приоритета.

- новый рецепт может быть предложен без точного аналога в истории;
- discovery объясняется кухней, форматом, временем, бюджетом, широтой корзины и
  реакцией на предыдущие рекомендации;
- бренд/SKU учитывает личную affinity, price band, замену и расстояние;
- supplier payment, ad bid и hidden margin boost не участвуют в organic rank;
- пользователь видит reason codes и может сменить режим/товар.

Примеры:

- «5 из 7 ингредиентов уже были в сегодняшнем чеке»;
- «нужно докупить два продукта»;
- «новый рецепт похож на быстрые блюда, которые вы сохраняли»;
- «уценённый вариант отмечен в магазине в 800 м».

## Как ранжируем

```text
recipe_score = relevance
             + current-basket coverage
             + repeat/discovery fit
             + time/budget fit
             - missing_count/cost penalty
             - constraint violations
```

Сначала работают relevance и safety thresholds. Затем среди сопоставимых
кандидатов рецепты с меньшим числом missing items идут выше. В режиме
`попробовать новое` допускается больше новых продуктов; пользователь может
пересортировать по `меньше докупить / дешевле / новое`.

## Где деньги

```text
A. Рецепт создаёт новый purchase day
   → contribution дополнительной корзины

B. Рецепт расширяет плановую корзину
   → incremental whole-basket contribution

C. Уценённый SKU продаётся лучше текущего baseline
   → incremental rescue value
```

Только A отвечает case primary по частоте. B и C — реальные business outcomes,
но не замена purchase-frequency uplift.

Для доставки отдельно считаются picking/last-mile economics и channel shift.
Заказ доставки не является дополнительной покупкой, если он просто заменил
обычный визит в X5.

## Метрики

| Уровень | Метрика |
|---|---|
| Case primary | `Δ distinct purchase days/user`, `ΔP(days ≥ N)` на 30/60 днях |
| Business | `Δ contribution margin / eligible user` |
| Rescue | incremental markdown value против действующего baseline |
| Recsys | relevance/hit rate и own-history vs shuffled-history ≥70% |
| Availability | markdown store-days, offers/user/30d, fallback rate |
| Diagnostics | opens, saves, recipe repeats, Domovoi returns |

Recipe feed доступен ежедневно за счёт full-price fallback. Это не означает
ежедневную уценку. Push получает frequency cap и отправляется только при
достаточной релевантности/availability.

## Домовой и личный progress

- продукты из следующего чека появляются в доме;
- рецепты и пользовательские замены сохраняются;
- нет голода, decay, streak и наказания за отсутствие;
- gambling-like `забрать / рискнуть` пока не входит в PoC;
- public leaderboard отсутствует.

Личный экран показывает:

- сохранённые/приготовленные рецепты;
- фактическую экономию на купленных markdown items;
- число rescue-позиций;
- развитие дома/аватара.

Формулировка «продуктов спасено» требует counterfactual. Без него безопаснее
писать «куплено из rescue-подбора».

## Четыре экрана PoC

1. **После чека:** продукты у Домового, режимы `из корзины / повторить / новое`,
   top рецептов, missing count и наличие уценки.
2. **Рецепт:** `куплено / есть дома / уценка / full-price / недоступно`, замены,
   сортировка и сохранение.
3. **Мой план:** магазин/зона в радиусе, обновление availability, выбор
   `заказать доставку / сохранить к следующему визиту`.
4. **Личная кухня:** новый чек, завершение ингредиентов, книга рецептов,
   Домовой, личная статистика и отдельная referral-карточка.

## Что проверяет PoC

```text
C0 current experience
C1 personalized recipes
C2 C1 + ingredient list и markdown/full-price выбор
C3 C2 + Домовой, книга и personal progress
```

Если `C2` увеличивает только корзину, это commerce-модуль, но не frequency core.
Если `C3` увеличивает только app/game return, вклад Домового в бизнес не
доказан.

## Основные риски

- markdown availability без брони быстро устаревает;
- full-price fallback превращает rescue в обычный recipe commerce;
- сортировка по missing count снижает персональную релевантность;
- доставка каннибализирует следующий визит вместо создания покупки;
- мясо и молочные категории требуют строгих safety gates;
- пользователь считывает ингредиенты как скрытый cross-sell;
- личное «спасено» обещает недоказанный counterfactual;
- Домовой повышает только retention игры.

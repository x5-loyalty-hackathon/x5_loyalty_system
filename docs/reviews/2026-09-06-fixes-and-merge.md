## Повторное независимое ревью и дополнительное исправление

Оба агента получили `ba929d2` из GitHub в собственные worktree прежних
независимых клонов. Новый контракт читали из закоммиченного ADR-005, без чата,
локальной ветки автора и отчёта другого агента. Оба закрыли исходные замечания,
но дали **request changes** по новым пограничным случаям:

| Находка | Исправление и проверка |
|---|---|
| ML-review: чек A за 04.09 содержит весь набор, B за 05.09 только часть. A→B и B→A давали разные дни награды; при использованном 04.09 — общий XP 20 против 40 | Все подходящие чеки сохраняются с покрытием SKU; до завершения выбирается первая полная корзина по времени покупки. Восемь HTTP-перестановок: частичное/полное перекрытие, оба порядка, свободный/занятый лимит; после завершения основание неизменно |
| Mobile-review: ready завершён на save по текущему чеку, но «повторить чек» создаёт новую покупку другого дня | UI предлагает повтор только собственного сохранённого события; handler запрещает создавать новый чек для completed-on-save. Настоящий provider/API проверяет отсутствие вызова receipt endpoint и неизменность чеков, дней и XP |

Это дополнительные механические исправления принятого правила, не новый размер
бонуса и не расширение игровых механик. Граница времени доказательства уточнена
в ADR-005 §6: учитываются события, пришедшие до завершения, не неизвестные будущие.

Локальный повтор после этих исправлений: **417 Python passed, 3 skipped**

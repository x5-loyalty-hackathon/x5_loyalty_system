# Состав и выполнимая корзина — правила PoC

07.09.2026. Уточнение действующего API 1.3 по дефектам S1–S3 из
[аудита](reviews/2026-09-07-poc-system-safety-audit.md). Не новая модель или экран.

## Исключаем фактическую упаковку

`InventoryProduct.ingredient_ids` и `contained_categories` проверяются целиком,
вместе с основной `category`. Это относится и к сырому/составному товару, и к
готовому блюду. «Кабачки со сливками» нельзя использовать при исключённом молоке,
даже если рецепт требует только кабачок.

В `ReceiptItem` добавлено необязательное `contained_categories` (по умолчанию
пусто). Из исключённой упаковки чека нельзя получить «безопасный» домашний
ингредиент. Если в магазине есть допустимая замена, рецепт остаётся с докупкой;
иначе cook скрывается. Допустимый ready не теряется вместе с cook.

Это проверки **известных** атрибутов, не восстановление неизвестного состава
сырого продукта, не доказательство свежести/остатка дома и не медицинская гарантия.
Явный `home_ingredient_ids` остаётся заявлением пользователя о сыром ингредиенте.

## Неизвестный состав готового блюда

Дополнительные поля входного SKU:

| Поле | Значение |
|---|---|
| `composition_complete` | `false` по умолчанию; `true` означает полное сопоставление состава конкретного SKU |
| `composition_source` | `unknown` (по умолчанию), `synthetic_fixture`, `manufacturer` или `recipe_proxy` |

Если пользователь задал хотя бы одно исключение ингредиента **или категории**,
ready допускается только при полном непустом составе, заполненных категориях
и источнике `synthetic_fixture` либо `manufacturer`. Известное пересечение
с исключением блокирует товар независимо от этих флагов.

`recipe_proxy` (включая аналог food.ru), неполный или неизвестный состав не
подтверждают совместимость: такой ready скрывается. Внутренний код отказа —
`ready_composition_unconfirmed`; новые публичные reason codes не вводятся.
Без пользовательских исключений неизвестный состав сам по себе не запрещает
ready; срок, наличие, пригодность, meal intent и остальные guards сохраняются.

Два готовых блюда mobile и пример омлета явно помечены `synthetic_fixture`:
полнота относится к **синтетической фикстуре**, не к товару X5. Поля необязательны,
но старые входы без них при исключениях получают более строгую фильтрацию.
Для реального каталога источник должен назначать доверенный адаптер, не клиент.

## Одна закупаемая позиция на ингредиент

- Совпадение только категории не доказывает, что SKU — нужный ингредиент.
  Пустой `ingredient_ids` не участвует в cook-подборе.
- SKU, попадающий сразу в несколько обязательных недостающих групп рецепта,
  исключается из этих групп **до выбора магазина**. Остаются однозначные альтернативы.
- Если после этого корзину нельзя собрать в одной точке с общим способом
  получения, cook не предлагается как полный. Другой допустимый магазин/ready сохраняются.
- Текущий контракт не распределяет граммы/упаковки между ингредиентами.
  Поздние проверки выбора, чека и XP остаются обязательными и не ослаблены.

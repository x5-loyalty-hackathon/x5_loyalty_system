# Остаточные gaps после подключения API 1.3

Обновлено 07.09.2026. Источник решений — `experiment/vxofi`.
Предыдущий список отражал контракт 1.0 и больше не является backlog API.
Приоритеты для финальной сдачи и свежие коммиты коллег:
[чеклист PoC](../../docs/poc-readiness.md). Ограничения ниже не все блокируют PoC.

## Уже закрыто существующим API

- `POST /api/v1/meal-recommendations`: challenge selection, cook/ready,
  причины, безопасные SKU, уценка, fulfillment и одна cook-точка.
- `POST/GET /api/v1/saved-recipes`: книга и следующий repeat-запрос.
- `POST /api/v1/meal-plans`: выбранный route, SKU и способ получения.
- `POST /api/v1/events/receipts`: прогресс и состояние плана по чеку.
- `POST /api/v1/meal-plans/{id}/complete-cook`: отдельное подтверждение готовки.
- `GET /api/v1/progress/{user_id}`: XP, блюда, покупки, экономия, private rank.

Не нужны отдельные API для случайного каталога замен, рекламной готовой еды
или промышленной корзины только ради этого demo. Уценка разрешена продуктовым
решением и подключена как явный выбор; старый запрет отменён.

## Реальные оставшиеся ограничения

1. **Поправка к домашнему наличию.** `home_ingredient_ids` добавляет наличие;
   отменить наличие из недавнего чека (`закончилось`) нельзя. Текущий UI честно
   показывает ограничение вместо неработающего переключателя.
2. **Состав и инструкция.** Нужны согласованные порции/количества и проверенные
   инструкции каталога. В UI — только три local demo-инструкции с проверкой
   совпадения ingredient IDs, без выдуманной инструкции для неизвестного рецепта.
3. **Возврат к плану.** API/UI не предоставляют историю планов для восстановления
   после перезапуска приложения; серверное состояние process-local.
4. **Серверная проверка плана — закрыта для PoC.** API 1.3 связывает план
   с выданным `offer_id`, пользователем, разрешёнными SKU/route/fulfillment
   и покупочным основанием. Это не production-auth и не кассовая интеграция.
5. **Реальная доставка и остатки.** Будущий визит/доставка — намерение, не
   резервирование. Расстояния, availability и часы синтетические, стоимость
   доставки неизвестна, количественная достаточность упаковок не рассчитывается.
   Адреса, корзина и оформление — в основном приложении, отсутствующем здесь.
   [Host-адаптер](../../docs/commerce-host.md) задаёт границу подключения;
   в PoC включена явная симуляция покупки по умолчанию, поэтому ручной показ
   работает без основного приложения. Настоящей оплаты/заказа при этом нет.
6. **Игровой интерфейс.** XP/уровень/личные счётчики подключены. Украшения,
   frontend рефералов и приватной позиции остаются отдельными задачами.
   Принятые API покупки уже добавляются на кухню локально; отдельный серверный
   endpoint холодильника ради этого demo не понадобился.

Точный цифровой холодильник с автоматическим вычислением сроков годности,
геокодер, пуши и кассовая интеграция не включаются в этот этап.

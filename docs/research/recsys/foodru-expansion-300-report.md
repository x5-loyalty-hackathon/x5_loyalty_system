# Расширение food.ru до 301 соответствия

Цель достигнута: **301 из 601 товаров** получил рецепт и предполагаемый состав.
База сравнения — коммит `f6f4b20`: 844 рецепта и 266 соответствий. Правила
`foodru-name-v2` и порог автоматического принятия 0.72 не менялись.

## Что дало расширение

| Показатель | До | После |
|---|---:|---:|
| Рецепты | 844 | 1 209 |
| Принятые товары | 266 | 301 |
| На проверке | 333 | 298 |
| Без кандидата | 2 | 2 |
| Разные рецепты в принятых парах | 191 | 213 |
| Рецепты с рейтингом | 493 | 675 |
| Рецепты с комментариями | 219 | 285 |
| Комментарии | 694 | 846 |

Добавлены **35 соответствий**: 19 используют новые рецепты, 16 — просмотренные
кандидаты из прежних 844. Все прежние 266 товаров сохранили аналог; у 3 выбран
другой рецепт. Из итоговых 301 пары **278 выбраны алгоритмом, 23 — решением
агента после просмотра**. Последнее число включает исправление кандидатов и
сохранение прежних удачных рецептов, а не только прирост покрытия.

## Сбор новых данных

Из сохранённой карты food.ru (166 814 URL) отобраны 360 ещё не собранных
страниц под 170 товаров без принятой пары. Отбор идёт по очереди кандидатов
каждого товара, до четырёх страниц на товар, с общим пределом 360 и оценкой
отбора не ниже 0.65. Это порог поиска страниц, а не принятия соответствия.
Затем адресно собраны ещё пять рецептов сырного салата.

Все **365 новых страниц разобраны без ошибок**, прежние 844 записи рецептов
сохранены в точности. Итого 1 209 рецептов, все с опубликованным составом.
Полный состав источника не редактировался. План, URL и целевые товары находятся
в [`expansion_plan.json`](../../../recsys/data/foodru/expansion_plan.json),
итоговый список адресов — в `recipe_urls.txt`.

Рейтинги и комментарии сохраняются по прежним правилам: только доступные
в HTML карточки, без имён и профилей пользователей. Сбор использовал три
потока и общий интервал не менее секунды между началами HTTP-запросов.

## Просмотр кандидатов и поправки

Агент просмотрел названия и составы 35 новых принятых пар и 3 заменённых.
Отдельно разобраны сомнительные предложения алгоритма. Например:

- Найден рецепт грибного супа, в котором названа лапша, но её нет в составе.
  Выбран другой рецепт, где одновременно присутствуют шампиньоны и лапша.
- Рецепт пиццы «Четыре сыра» содержал только четыре сыра. Выбран полный
  рецепт с тестом и четырьмя видами сыра.
- Для сырного салата выбран сыр с яйцами, чесноком и майонезом; варианты
  листового салата с бурратой и салата с мясом отклонены.
- У оладий рис оказался внутри изделия. Отдельный гарнир с овощами не
  подтверждён, товар оставлен в `review`.
- У мини-запеканки с вишней не указана основа, а новый рецепт содержит
  кокосовую и овсяную муку с семечками. Этот случай оставлен в `review`.
- Для пиццы пепперони сохранён рецепт с пепперони в составе, для кокосовой
  рисовой каши — рецепт без новых яблок, граната и миндаля.

В прежнем наборе подходили, например, наггетсы «Вязанка», блины «Солнцепек»,
шоколадные эклеры Poppies, гаспачо «из натуральных помидоров», круассан
«с добавлением сливочного масла» и тыквенный `Cуп` с латинской первой буквой.
Описательные слова и ошибки написания мешали автоматическому решению.
Есть и явные допущения варианта блюда: базовый хумус для товара с указанием
Иерусалима и чиабатта для варианта «Рустик». Они записаны в обоснованиях,
а не выдаются за совпадение промышленной рецептуры.

[`reviewed_overrides.json`](../../../recsys/data/foodru/reviewed_overrides.json)
содержит **25 решений: 23 выбора рецепта и 2 отклонения**. Для каждого есть
ID и причина, `reviewer=agent`, `manufacturer_verified=false`. Сборка сама
подхватывает этот файл; отдельный `--overrides` может выбрать другой файл.
Механические причины проверки кандидатов сохранены, решение агента видно
отдельно. Смешанные группы блюда и подачи по-прежнему блокируют принятие.

## Проверки и воспроизводимость

```bash
.venv/bin/python -m recsys.offline.foodru build
.venv/bin/python -m recsys.offline.foodru_evaluate \
  --baseline-ref f6f4b20 --allow-expanded-snapshot
.venv/bin/python -m pytest tests/test_foodru_offline.py \
  tests/test_recsys_ready_food_pairs.py tests/test_recsys_merge_boundaries.py
```

**89 тестов проходят**, включая сохранение исходных рецептов при расширении,
применение поправок при повторной сборке, полноту выбранных супа и пиццы,
отделение подачи и границы текущего рекомендательного сервиса.

Два повторных запуска сборки и оценки с `PYTHONHASHSEED=123` и `987` дали
побайтно одинаковые 8 производных JSON/CSV/TXT-файлов. Поправки применились
автоматически. Проверены неизменность исходного каталога, сохранение всех 844
прежних записей рецептов и согласованность контрольных сумм плана и отчёта.

[`quality_report.json`](../../../recsys/data/foodru/quality_report.json) связывает
результат с каталогом, снимком рецептов, поправками и `matches.json` через
SHA-256. [`changes.csv`](../../../recsys/data/foodru/changes.csv) показывает
изменения относительно 266 пар из v2. Добавления разрешены явно; сравнение
отклоняет исчезновение или изменение любой прежней записи рецепта.

На 39 прежних размеченных контрольных парах решения правил не изменились.
Эта выборка использовалась при разработке и **не оценивает независимо новые
35 пар или решения агента**. Точную долю правильных соответствий всего каталога
по ней заявлять нельзя. Общий matcher также не выявляет все неполные рецепты:
часть ошибок этого сбора устранена именно сохранёнными решениями после просмотра.

Результат — офлайн mock. Состав остаётся `recipe_name_proxy`, его количества
относятся ко всему рецепту. Подтверждённый состав производителя и новые
онлайн-интеграции не появились.

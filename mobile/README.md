## Запуск

Нужны Node.js 24 и Python-окружение проекта. Из корня репозитория:

```bash
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

По умолчанию backend использует детерминированный `mock`. Интегрированный
синтетически обученный ML включается при запуске backend:

```bash
RECOMMENDATION_ENGINE=model .venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

В `/health` должны быть `recommendation_engine=model`, `model_fallback=false`.
Модель обучается при старте; включение ML не расширяет автоматически мобильный
fixture с трёх блюд до всех 47 рецептов обучающего каталога.

В другом терминале:

```bash
cd mobile
npm ci --legacy-peer-deps --ignore-scripts --no-audit --no-fund
npm run web
```

Открыть `http://localhost:8081`. API по умолчанию — `http://127.0.0.1:8000`;
для localhost/127.0.0.1:8081 настроен явный CORS.

Для телефона: в `mobile/.env` указать `EXPO_PUBLIC_API_BASE_URL=http://<LAN-IP-Mac>:8000`,
запустить `npm start` и открыть QR в совместимом Expo Go. IP Mac можно получить
через `ipconfig getifaddr en0`. Телефон и Mac должны видеть друг друга по сети;
localhost на телефоне указывает на сам телефон. После смены .env перезапустить Expo.

## Что подключено

| Экран | Действие / источник |
|---|---|
| `/` | Кухня и панель; вход перед доставкой/после покупки; возврат к черновику; «Готовить» после покупки; готовое — к прогрессу |
| `/recipes` | Meal API, серверный порядок и current/repeat/explore; адресное управление вне игры |
| `/recipe` | Cook/ready, причины, ингредиенты, книга; при нулевой докупке сохранение задания и сразу готовка |
| `/products` | SKU из API, уценённые/обычные варианты, черновик блюда и передача в оформление приложения; не игровой чек/касса |
| `/profile` | Серверные XP, покупки, блюда, уценка; переход в «Убранство кухни» |
| `/kitchen-style` | Десять предметов оформления из каталога коллеги; выбор открытых предметов пока локальный |

Шесть экранов унаследованы от UI коллег; нижние вкладки — кухня, рецепты,
профиль. «Мой план» открывается из кухни или карточки блюда, а не отдельной
вкладкой. Ready и доставка не стали отдельными экранами. Это ещё не интеграция
в промышленное приложение X5.

Оформление теперь показывается слоями/спрайтами `mobile-polish`. Сохранена
его лестница 2, 4, …, 20 без самостоятельной перебалансировки; согласование
продуктового баланса ещё открыто. XP приходит с сервера и не расходуется,
но выбор предметов хранится в клиентской сессии: это **не серверное сохранение
оформления**. Перезапуск клиента теряет этот выбор; смена demo-профиля его
очищает. Разблокировка на экране — клиентская проверка серверного уровня.

Прежние `HomeDecorationSheet`, `KitchenWallpaper` и
серверный каталог обоев сохранены в коде/checkpoint `170c828`, но **не подключены
к текущим экранам**. Не добавлять их кнопки поверх версии коллеги без
согласования. [Прежний серверный контракт](../docs/home-decoration-contract.md)
не описывает сохранение десяти новых предметов; это отдельный шаг интеграции.

`mealRequest.json` сохраняет исходный fixture и три рецепта. `recommendationRequest.ts`
добавляет три синтетических примера внутри готовящих домохозяйств, по четыре
прошлых чека за 19–31 августа и отдельный текущий чек от 4 сентября. Это не новая
бизнес-сегментация и не репрезентативная выборка покупателей X5.

| Demo-покупатель | API user_id | Покупки / предпочтения |
|---|---|---|
| Семья · паста | `user_mobile_12` | Паста, фарш, томаты и сыр; исходный текущий чек сохранён |
| Овощные ужины | `user_mobile_vegetable` | Овощи, паста и сыр; явное исключение мяса; текущие паста, томаты и морковь |
| Домашний суп | `user_mobile_soup` | Курица, морковь, лук и другие овощи; текущая основа супа |

По умолчанию выбран «Семья · паста». С согласия vxofi (UI1, 06.09) только внизу
«Профиля» размещён переключатель с подписью **«Только для демонстрации —
синтетические покупатели»**. Это не переключение реальных аккаунтов X5.
`buildRecommendationRequest` передаёт историю и предпочтения выбранного профиля настоящему API,
а также поддерживает разные demo-места в API (их переключателей в игре нет). Каталог рецептов
общий; синтетические остатки дополнены пастой, фаршем, томатами и сыром, чтобы
другой покупатель мог собрать их в том же магазине. Все user/receipt IDs раздельны;
прежние helpers без аргумента используют «Семья · паста».

При переключении сбрасываются локальные кухня, план, попытка отправки плана/чека,
готовка, выбранные SKU, место и способ получения. Книга и XP очищаются на экране
и перечитываются для активного user_id; при возврате сохранённые сервером книга
и прогресс возвращаются. Кухня снова показывает текущий чек выбранного профиля,
без восстановления покупок прошлой сессии. Поздние ответы старой сессии, включая
успех/ошибку действий и переход A → B → A, не меняют новый экран. Уже принятая
сервером операция остаётся у своего пользователя; переключение не отменяет покупку.

`purchase_history` — контекст ML, не подтверждённые события прогресса. Перед выдачей
только текущий чек явно проходит receipt endpoint с постоянным ID; повторная загрузка
идемпотентна и сама по себе не даёт XP. История не превращается в домашние запасы.

`recipeDetails.ts` содержит инструкции трёх demo-рецептов; они показываются
только при совпадении ingredient IDs с ответом API. Это не сгенерированные ML
инструкции и не полноценный проверенный кулинарный каталог.

Локальный `src/data/demo.ts` и старый `receiptEvent.ts` сохранены как дизайн-референсы,
но больше не используются сценарием. Нет примеси локальных блюд к выдаче,
фиктивных рейтингов товаров, сроков годности из чека и фиксированного чека молока.

`visual-baseline.test.mjs` контролирует это без GitHub. Ниже — предыдущие прогоны.

```bash
npm run typecheck

npm run test:api
X5_TEST_ENGINE=model npm run test:api
npm run export:check -- --max-workers 2
```

`test:api` вызывает настоящий FastAPI через TestClient из Python-процесса и

## Ручной smoke перед показом

Действует [ADR-005](../docs/decisions/005-game-tasks-and-xp.md): обычная покупка
без выбранного задания не даёт XP; готовка/ready с подтверждением — до 20 XP,
максимум один бонус на покупочный день. Текущий synthetic-чек проходит receipt
endpoint до выдачи; это ещё не новая покупка из игры.

1. На чистом backend открыть «Рецепты», выбрать «Спагетти болоньезе»; сохранить
   рецепт в книгу и проверить «Повторить». За сохранение XP нет.
2. В товарах выбрать уценку лука. Уйти на Кухню и вернуться через «Мой план» —
   состав сохранён без отдельной кнопки. Обычный товар остаётся альтернативой.
3. Перед кнопкой увидеть «Демо: оформление и покупка моделируются». Нажать
   «К оформлению»: встроенный обработчик отправит синтетический чек в backend.
   Появится «Демо-покупка подтверждена», продукты добавятся на Кухню. За одну
   покупку ингредиентов XP ещё нет; дополнительного подключения не требуется.
4. После покупки и принятого чека — Кухня → «Готовить» → «Я приготовил».
   20 XP при свободном лимите. Повтор после сетевой ошибки не удваивает награду.
5. Выбрать блюдо заново → «Купить готовое». Приложение подтверждает покупку
   выбранного готового SKU. Задание завершается без готовки; за тот же покупочный
   день второй бонус не выдаётся. На Кухне доступен «Мой прогресс».
6. «Паста с томатами», если всё есть: прямой старт готовки без оформления и
   нового чека. Подтверждённый текущий чек может дать награду за свой покупочный
   день; HOME без подходящей покупки даёт 0 XP.
7. Внизу профиля сменить синтетического покупателя и вернуться обратно.
   Уценка доступна, доставка по умолчанию; чужие план/кухня/XP не переносятся.
8. Проверить раскрытие/жесты панели кухни, прокрутку шагов и «Убранство кухни».
   Выбор десяти предметов пока локальный, XP не тратятся, упаковки не списываются.

Сквозной browser smoke обычной сборки без подстановки обработчика из теста:
[команда и ограничения](../docs/commerce-host.md#как-проверять-и-демонстрировать).
Demo-часы: 05.09.2026 12:00 МСК; исходный чек от 04.09 — другой покупочный день.
Физический телефон и доступность backend по LAN проверяет демонстратор.

## Что ещё не готово

- Ручной прогон на телефоне и UI-полировка с автором макетов.
- Проверенные инструкции за пределами трёх рецептов и финальная оценка качества
  ML на отдельной выборке; три cooking-примера есть в fixtures и тестах,
  переключатель синтетических покупателей уже находится внизу профиля.
- Пользовательская поправка «закончилось» и количество порций/упаковок.
- Кухня начинается с недавнего чека активного профиля и пополняется покупками
  текущей сессии после принятия сервером. При смене профиля/перезапуске список сбрасывается;
  это не точный остаток, не источник сроков годности и не автоматический ввод HOME в ML.
- Серверное сохранение/проверка нового каталога оформления и согласование
  лестницы наград; frontend рефералов и приватного ранга.
- Книга живёт до перезапуска backend. Текущий план UI не переживает перезапуск
  приложения; переход к другому блюду не даёт открыть старый план из истории.
- Реальные остатки, актуализация цен на будущий визит, заказ доставки и оплата
  отсутствуют. Нельзя обещать наличие уценки завтра; на экране есть предупреждение.
- Сервер связывает план с собственным оффером и проверенными synthetic-чеками.
  Но нет production-auth, кассовой интеграции и доказательства реальности
  входного чека/каталога: эту границу нельзя считать промышленной защитой.
- Данные синтетические. Никакой измеренный причинный uplift этой сборкой не заявляется.

# Как работать с репозиторием

Это стартовое рабочее соглашение для первых pull request, а не продуктовое или
архитектурное решение. Команда может изменить процесс, когда договорится на
kickoff.

## Перед началом задачи

1. Проверьте [текущее состояние](docs/project-status.md) и открытые issues.
2. Для нетривиальной работы создайте или возьмите issue с понятным результатом.
3. Если работа требует нового продуктового или инженерного решения, сначала
   добавьте предложение в [журнал решений](docs/decision-log.md).
4. Создайте ветку от свежей `main`.

```bash
git switch main
git pull --rebase origin main
git switch -c <type>/<short-task-name>
```

Типы веток: `feat`, `fix`, `docs`, `experiment`, `test`, `chore`.

## Коммиты

Используем короткий формат Conventional Commits:

```text
feat: add challenge selection baseline
fix: prevent duplicate referral reward
docs: record target segment decision
```

Один коммит должен описывать одно логически связанное изменение. Не коммитьте
секреты, реальные персональные данные, большие сгенерированные датасеты и
локальные артефакты.

## Pull request

- Делайте PR небольшим и с одним проверяемым результатом.
- Свяжите его с issue через `Closes #<number>`, если issue существует.
- Укажите, что изменено, как проверено и какие допущения сделаны.
- Для изменения поведения приложите скриншот, пример ответа API или результат
  теста/симуляции.
- Перед merge нужен review хотя бы одного другого участника.
- Предпочтительный способ merge — **Squash and merge**.

Если новая ветка отстала от `main`, обновите её:

```bash
git fetch origin
git rebase origin/main
git push --force-with-lease
```

`--force-with-lease` допустим только для собственной рабочей ветки, не для
`main` и не для общей ветки другого участника.

## Definition of Done

Изменение готово к merge, когда:

- реализован заявленный в issue/PR результат;
- пройдены относящиеся к изменению проверки;
- обновлена документация или явно указано, почему это не требуется;
- новые допущения и решения зафиксированы;
- в diff нет секретов, ПДн и случайных сгенерированных файлов;
- PR просмотрен другим участником.

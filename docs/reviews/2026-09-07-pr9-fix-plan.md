# PR #9: план исправлений и граница игры

Основание: согласованный в чате список исправлений, 07.09.2026.
Входящий визуал — `feat/mobile-polish@30005a6`; изменения вносим в
`experiment/vxofi`, без прямого push в main. Последующие коммиты коллеги
не считаются автоматически просмотренными.

## 1. Что исправляем

1. Принять текущий визуал PR без перестановки экранов, кнопок и ассетов.
2. Выбор товаров — автоматически сохраняемый в игровой сессии черновик:
   уход на Кухню или просмотр выдачи не удаляет его. Явный выбор другого блюда
   заменяет текущий черновик. Перезапуск и смена синтетического покупателя пока
   сбрасывают сессию; долговременная корзина принадлежит приложению магазина.
3. Существующая нижняя кнопка — «К оформлению». Перед передачей в приложение
   внутренне фиксируем выбранное задание/оффер/SKU. Кнопка не подтверждает чек,
   не запускает готовку и не обещает безусловные 20 XP.
4. Каталог, обычная корзина, адреса, доставка и оплата — экраны приложения
   магазина, не новые игровые экраны. В этом репозитории их нет: добавляем
   интерфейс подключения внешнего оформления, а не их имитацию внутри игры.
   Без подключённого приложения показываем сообщение в существующем месте
   ошибок. Открытие/отмена оформления не создают синтетическую покупку.
5. Готовка после покупки доступна на Кухне через существующее действие плана.
   Готовое блюдо завершается по подходящему принятому чеку, без готовки.
6. Выбирать и показывать один и тот же готовый SKU, доступный для текущего
   способа получения. Не менять доставку на визит молча. Смена demo-профиля
   не отключает принятую доступность уценки.
7. Повтор после неопределённого сетевого результата использует тот же запрос,
   plan ID и чек. Отмена оформления оставляет выбранное задание и корзину,
   но не считается покупкой или выполнением. Защита XP остаётся серверной.

## 2. Сверка с контрактами

| Документ | Результат сверки |
|---|---|
| ADR-005: задания и XP | Сохраняется: явный выбор + выданный оффер + подходящая покупка + завершение. Для cook подтверждение готовки отдельно; ready закрывает чек. Лимит — один meal-бонус на покупочный день. «Сохранение плана» — внутренний запрос, не обязательная пользовательская кнопка. |
| ADR-004: магазин и книга | Проверка одной точки и fulfillment остаётся. Адрес задаёт основное приложение, отдельного адресного UI в игре нет. |
| Технический дизайн | Промышленная касса, оплата, бронь и интеграция с X5 вне PoC. Внешний обработчик оформления — граница подключения, не заявление о готовой интеграции. |
| branch-merge-plan R1–R3 | Позднее уточнение чата: адреса вне игры; «Подобрать блюдо» принято; отдельная кнопка готового на карточке принята. GET кухни/инструкций — после merge, сюда не включаем. |

Противоречий с действующим правилом XP нет. Прежние предложения добавить
игровое окно оплаты, адреса в игре или последовательность «сохранить → чек →
готовить» на одной кнопке **не реализуем**.

## 3. Проверки перед push

- Реальные обработчики экранов: кнопка оформления не вызывает чек/готовку;
  существующая кнопка на Кухне открывает готовку только при собранных продуктах.
- Черновик переживает навигацию; выбор другого блюда и смена профиля изолированы.
- Смешанные delivery/next_visit SKU; совпадение карточки и выбранного товара;
  профиль A → B → A; уценка не исчезает.
- Внешнее оформление: отсутствие подключения, отмена, успешный чек, потерянный
  ответ и повтор, смена профиля во время запроса; отсутствие лишних XP.
- Client tests, TypeScript, API smoke на mock/model; экспорт; браузерный smoke.
- Эталон исходников обновить на точный PR-коммит, отдельно перечислить только
  согласованные поведенческие/текстовые изменения. Старый визуал не восстанавливать.
- Зафиксировать фактический результат и ограничения, коммитить только файлы
  этого исправления. Незавершённые ML-правки и личные research-файлы не трогать.

Статус: план и сверка зафиксированы; результаты проверки будут в памятке
этого исправления. Проверка физического телефона остаётся у демонстратора.

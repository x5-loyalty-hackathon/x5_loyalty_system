# Интеграция мобильного демо — 05.09.2026

Источник системных и продуктовых решений — `experiment/vxofi`, API 1.2,
[ADR-003](decisions/003-challenge-mode-selection.md) и
[ADR-004](decisions/004-recipe-book-and-shopping-context.md).
Переносим интерфейс `feat/mobile-app@2fb4a33`, не его устаревшие допущения.
ML подключается позднее через существующий backend; этот этап работает на mock.

## План и критерии приёмки

1. **Перенести фронт, сохранив оформление коллег.** Не затронуть ML и личные
   исследования. Проверка: чистое слияние, TypeScript и сборка Expo.
2. **Подключить meal API 1.2.** Типы, рекомендации, выбор режима/route,
   объяснения и предупреждения. Пустой ответ остаётся пустым, ошибка не
   маскируется локальной выдачей. Mock явно подписан; сервер определяет порядок.
3. **Замкнуть пользовательский сценарий.** Вход «Что поесть?» до сборки заказа
   и после покупки → рецепт/готовое блюдо → книга рецептов → план доставки или
   следующего визита → synthetic-чек выбранных SKU → подтверждение готовки →
   прогресс. Если всё дома, не требовать покупку. Сохранение рецепта не даёт XP.
4. **Согласовать товары и контекст.** Дом/работа на синтетических расстояниях,
   выбор полного магазина, замены только из серверных вариантов ингредиента,
   уценка по желанию, явные цены упаковок и отсутствие брони. Нельзя незаметно
   сменить магазин, сохранить старую корзину после смены блюда/контекста или
   подменить отсутствующее готовое блюдо произвольным товаром.
5. **Проверить и передать.** Автотесты преобразований и переходов, backend
   интеграционные тесты на мобильных fixtures, TypeScript, Expo export, CI.
   В README — запуск и ручной smoke на устройстве; в статусе — фактический
   результат и ограничения, а не обещания.

## Обязательные отрицательные проверки

- Пустая выдача, сетевой сбой, несовместимая версия API; нет «фейкового live».
- Явный `explore`, отсутствие ready-варианта, пустая книга; нет filler-рецептов.
- Повтор сохранения/чека/готовки не удваивает награды; HTTP 200 с `rejected`
  или `pending_review` не отображается как успешная покупка.
- Cook завершается отдельно от чека; ready завершается подходящим чеком.
- Все товары дома: пустой список покупок допустим, пустой чек — нет.
- Смена режима/контекста не позволяет применить запоздавший сетевой ответ или
  отправить план от предыдущего выбора.

## Границы этапа

Не меняем ранжирование, XP, экономику и продуктовые решения. Не строим checkout,
реальные остатки, геокодер, авторизацию или уведомления. Данные, чеки и расстояния
синтетические; состояние сервера живёт до его перезапуска.

Отдельные последующие задачи, **не выдавать за готовое**: отрицательная поправка
к наличию из чека («закончилось», текущий API умеет только добавлять наличие),
выбор украшения дома и согласование его графики, реальный ML, ручная проверка
на телефоне. Убрать ложные сроки годности из текущего интерфейса уже сейчас.

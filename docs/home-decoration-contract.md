## Принято и что выбрано для первого показа

Пользователь меняет **отдельный элемент**, а не покупает обязательный набор
оформления. Можно выбрать будущую цель; открытые варианты свободно переключаются.
Доступ зависит от общего серверного уровня, XP не расходуются. Конкретный рецепт
не привязан к конкретному оформлению. Просмотр, выбор цели и применение не дают XP.

Первый элемент — **обои**: заметная площадь комнаты, без перестановки продуктов,
мебели и персонажа. Гарнитур и пол — возможные следующие элементы, не обещание
их готовности в этой версии. Визуальная реализация использует отдельный слой
отрисовки комнаты; неизменяемые предметы не перекрашиваются вместе со стеной.

Ниже редактируемые **demo-настройки**, а не измеренный баланс удержания:

| ID | Название | Уровень | Всего XP |
|---|---|---:|---:|
| wallpaper_default | Тёплый дом | 1 | 0 |
| wallpaper_mint | Мятное утро | 2 | 50 |
| wallpaper_sunset | Персиковый закат | 2 | 50 |
| wallpaper_sky | Небесная кухня | 2 | 50 |
| wallpaper_night | Звёздный вечер | 3 | 100 |
| wallpaper_berry | Ягодный уют | 4 | 150 |

В начале открываются три альтернативы, на последующих уровнях — по одной.
50 XP на уровень и 20 XP за подтверждённое задание не меняются. Следовательно,
три награждённых задания на разных покупочных днях дают 60 XP и второй уровень;
три нажатия в один день его не открывают. Реферальный XP остаётся по своему
существующему контракту. В UI не добавляется кнопка начисления XP.

## API и состояние

`GET /api/v1/home-decoration/{user_id}` возвращает:

```json
{
  "user_id": "demo-user",
  "avatar_xp": 0,
  "avatar_level": 1,
  "goal_item_id": null,
  "applied_item_id": "wallpaper_default",
  "items": [{
    "item_id": "wallpaper_default",
    "title": "Тёплый дом",
    "description": "Базовое оформление кухни",
    "unlock_level": 1,
    "required_xp": 0,
    "unlocked": true
  }]
}
```

Массив `items` содержит весь каталог, включая закрытые варианты.

- `POST /api/v1/home-decoration/{user_id}/goal`, тело `{"item_id": "wallpaper_mint"}`:
  выбрать цель, в том числе ещё закрытую. `{"item_id": null}` снимает цель.
- `POST /api/v1/home-decoration/{user_id}/apply`, тело `{"item_id": "wallpaper_mint"}`:
  применить открытое оформление. Возвращает тот же полный snapshot. Выбранная
  цель сохраняется, чтобы было видно, что она достигнута; можно выбрать другую.
- Неизвестный ID — HTTP 404; применение закрытого — HTTP 409. Невалидное тело
  и дополнительные поля вроде клиентского XP/уровня — HTTP 422.
- Повтор того же выбора идемпотентен. При ошибке прежнее оформление и цель
  сохраняются. Доступ проверяет сервер под общей блокировкой состояния.

Источник доступа — существующий ledger наград в `InMemoryStateRepository`,
не цифры от клиента. Оформление хранится отдельно по `user_id`: чтение/смена
декора не создаёт участника рейтинга и не меняет его метрики. Перезапуск клиента
восстанавливает оформление из API; перезапуск backend сбрасывает его вместе
с остальным process-local demo-состоянием. Production auth здесь не появляется:
задание `user_id` в URL не является проверкой личности.

## Клиент и проверки

В доме есть переход к выбору оформления; можно увидеть варианты, условия
открытия, выбрать цель и применить доступное. Предпросмотр явно отличается
от сохранённого оформления. Закрытый вариант нельзя выдать за применённый.
После подтверждённой награды доступ перечитывается с сервера. При смене
demo-покупателя очищается локальный декор; поздний ответ предыдущей сессии
(в том числе A → B → A) не меняет нового покупателя. Сетевая ошибка не сбрасывает
уже сохранённый вариант и допускает безопасный повтор.

Проверки: пороги 49/50/99/100/149/150 XP; повторные операции; чужие и
неизвестные ID; запрет клиентской подмены XP; отсутствие XP/изменения рейтинга
от декора; изоляция покупателей; сохранение при повторном GET; сброс backend;
реальный purchase-backed путь открытия; устаревшие клиентские ответы и retry.
Визуальный показ и API-тесты отмечаются раздельно.

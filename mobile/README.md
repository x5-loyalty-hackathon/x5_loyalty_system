# Мобильное демо «X5 Домовой»

React Native / Expo, адаптированное к API 1.3 в `experiment/vxofi`.
Системные решения этой ветки имеют приоритет над исходными mock-макетами.
[План первого этапа](../docs/mobile-integration-plan.md).
Актуальные исходные коммиты, адаптации и карта кода для работы из соседней ветки:
[памятка frontend + ML](../docs/integration-handoff.md).

## Запуск

Нужны Node.js 24 и Python-окружение проекта. Из корня репозитория:

```bash
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

По умолчанию backend использует детерминированный `mock`. Интегрированный
синтетически обученный ML включается при запуске backend:

```bash
RECOMMENDATION_ENGINE=model .venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

В `/health` должны быть `recommendation_engine=model`, `model_fallback=false`.
Модель обучается при старте; включение ML не расширяет автоматически мобильный
fixture с трёх блюд до всех 47 рецептов обучающего каталога.

В другом терминале:

```bash
cd mobile
npm ci --legacy-peer-deps --ignore-scripts --no-audit --no-fund
npm run web
```

Открыть `http://localhost:8081`. API по умолчанию — `http://127.0.0.1:8000`;
для localhost/127.0.0.1:8081 настроен явный CORS.

Для телефона: в `mobile/.env` указать `EXPO_PUBLIC_API_BASE_URL=http://<LAN-IP-Mac>:8000`,
запустить `npm start` и открыть QR в совместимом Expo Go. IP Mac можно получить
через `ipconfig getifaddr en0`. Телефон и Mac должны видеть друг друга по сети;
localhost на телефоне указывает на сам телефон. После смены .env перезапустить Expo.

## Что подключено

| Экран | Действие / источник |
|---|---|
| `/` | Кухня и панель; выбор обоев и цели; вход перед доставкой/после покупки; шаги и подтверждение готовки выбранного плана |
| `/recipes` | Meal API, серверный порядок и current/repeat/explore; выбор demo-покупателя и места |
| `/recipe` | Cook/ready из одного предложения, причины, ингредиенты, сохранение в книгу |
| `/products` | Один магазин, SKU только из API, уценка по выбору, план и demo-чек |
| `/profile` | Переключение demo-покупателя; его состояние на сервере: XP, покупки, блюда, уценка |

Пять маршрутов унаследованы от UI коллег; ready и доставка не стали отдельными
экранами. Это ещё не интеграция в промышленное приложение X5.

«Обои» в верхнем углу кухни открывают оформление отдельного элемента дома.
Каталог, цель, сохранённые обои и доступ приходят из `home-decoration` API:
три альтернативы на уровне 2, ещё по одной на уровнях 3 и 4. Закрытые варианты
можно посмотреть и выбрать целью; предпросмотр явно подписан и не применяет
оформление. Открытые обои переключаются бесплатно, XP не расходуются. Цель видна
и в основной панели кухни. Награды перечитывают доступ с сервера; новая сессия
клиента и возврат к demo-покупателю восстанавливают его оформление.

Обои нарисованы React Native Views поверх стены: общая координатная сетка
и вырезы сохраняют печь, полки, окно, горшок, продукты и Домового.
`kitchen-full.png` не изменяется. Операции и GET используют общую защиту от
устаревших ответов; смена профиля также различает A → B → A. При ошибке
последнее подтверждённое оформление сохраняется, действие можно повторить.
Автоматическое обновление после награды не скрывает ошибку применения,
если сервер не подтвердил выбранные обои. Подробнее — [контракт оформления](../docs/home-decoration-contract.md).

`mealRequest.json` сохраняет исходный fixture и три рецепта. `recommendationRequest.ts`
добавляет три синтетических примера внутри готовящих домохозяйств, по четыре
прошлых чека за 19–31 августа и отдельный текущий чек от 4 сентября. Это не новая
бизнес-сегментация и не репрезентативная выборка покупателей X5.

| Demo-покупатель | API user_id | Покупки / предпочтения |
|---|---|---|
| Семья · паста | `user_mobile_12` | Паста, фарш, томаты и сыр; исходный текущий чек сохранён |
| Овощные ужины | `user_mobile_vegetable` | Овощи, паста и сыр; явное исключение мяса; текущие паста, томаты и морковь |
| Домашний суп | `user_mobile_soup` | Курица, морковь, лук и другие овощи; текущая основа супа |

Селектор есть в подборе блюд и профиле; на кухне подписан активный покупатель.
`buildRecommendationRequest` передаёт его историю и предпочтения настоящему API,
а также меняет расстояния при выборе дома/работы/другого demo-места. Каталог рецептов
общий; синтетические остатки дополнены пастой, фаршем, томатами и сыром, чтобы
другой покупатель мог собрать их в том же магазине. Все user/receipt IDs раздельны;
прежние helpers без аргумента используют «Семья · паста».

При переключении сбрасываются локальные кухня, план, попытка отправки плана/чека,
готовка, выбранные SKU, место и способ получения. Книга и XP очищаются на экране
и перечитываются для активного user_id; при возврате сохранённые сервером книга
и прогресс возвращаются. Кухня снова показывает текущий чек выбранного профиля,
без восстановления покупок прошлой сессии. Поздние ответы старой сессии, включая
успех/ошибку действий и переход A → B → A, не меняют новый экран. Уже принятая
сервером операция остаётся у своего пользователя; переключение не отменяет покупку.

`purchase_history` — контекст ML, не подтверждённые события прогресса. Перед выдачей
только текущий чек явно проходит receipt endpoint с постоянным ID; повторная загрузка
идемпотентна и сама по себе не даёт XP. История не превращается в домашние запасы.

`recipeDetails.ts` содержит инструкции трёх demo-рецептов; они показываются
только при совпадении ingredient IDs с ответом API. Это не сгенерированные ML
инструкции и не полноценный проверенный кулинарный каталог.

Локальный `src/data/demo.ts` и старый `receiptEvent.ts` сохранены как дизайн-референсы,
но больше не используются сценарием. Нет примеси локальных блюд к выдаче,
фиктивных рейтингов товаров, сроков годности из чека и фиксированного чека молока.

## Проверки

```bash
npm run typecheck
npm test
npm run test:api
X5_TEST_ENGINE=model npm run test:api
npm run export:check -- --max-workers 2
```

`test:api` вызывает настоящий FastAPI через TestClient из Python-процесса и
использует те же TypeScript-сборщики запроса, корзины, плана и чека, что и UI.
Проверки переключения запускают также настоящий `DemoProvider` и `endpoints.ts`
с заменой только HTTP-транспорта на TestClient. Они проверяют отдельные книги,
планы, чеки, кухню и XP трёх пользователей, восстановление книги/XP при возврате
и задержанный ответ чека после серверной записи. Клиентские регрессии дополнительно
задерживают выдачу/книгу/прогресс, save-plan и complete-cook, включая A → B → A.
Нужен `../.venv/bin/python` или `X5_TEST_PYTHON`; в CI используется Python из PATH.
Backend-suite из корня: `.venv/bin/python -m pytest`.

Прогон C2 от 06.09.2026: **34 клиентских теста, 12 API на mock + 12 на model**,
TypeScript — успешно. Model-прогон требует `/health: model_fallback=false`.
На чистой книге фактическая выдача модели: у семьи паста с томатами (0.9649)
и болоньезе (0.8814); у овощного профиля паста (0.9425); у супового основной
вариант — суп (0.9606), альтернатива — паста с двумя докупками (0.1765).
Контроль с заменой **только истории** семьи на суповую меняет оценки пасты/болоньезе
на 0.5008/0.4540. Это проверка передачи истории в модель; числа не являются
экспертной оценкой качества, hit rate или измерением эффекта продукта.

Дополнение C6: **50 клиентских тестов, 13 API на mock + 13 на model**, TypeScript — успешно.
Проверки включают реальное открытие обоев при 60 XP за задания на трёх покупочных
днях, свободное применение без изменения прогресса, потерянный ответ и точный retry,
восстановление после смены профиля/нового клиента. Клиентские регрессии дополнительно
проверяют поздние GET/мутации, автоматическое обновление после ошибки и закрытие
с повторным открытием панели во время применения.

Проверены backend, клиентские обработчики/transport, сквозные TS/API-переходы
на обоих движках, TypeScript и Expo export для web/iOS/Android.
Точные результаты этой итерации — в [памятке](../docs/integration-handoff.md#как-проверить-после-своих-изменений).
Это **не** автоматизация нажатий по React-экранам, не native build и не
подтверждение визуального качества на телефоне. Checks
[PR #7](https://github.com/x5-loyalty-hackathon/x5_loyalty_system/pull/7) относятся
к предыдущей базе. C2 и связанная первая волна пока проверены локально, не
опубликованы; актуальные результаты — [отчёт волны](../docs/reviews/2026-09-06-poc-wave-1.md).

## Ручной smoke перед показом

**Состояние на 06.09:** API 1.3 реализует
[ADR-005](../docs/decisions/005-game-tasks-and-xp.md):
0 XP за обычную покупку без задания, 20 XP за выбранное выполненное задание с
подходящей покупкой, максимум один бонус на покупочный день. Клиент передаёт
серверный `offer_id` и показывает статус награды; готовка без награды разрешена.
Текущий synthetic-чек перед выдачей явно проходит receipt endpoint, не начисляя XP.

1. Перезапустить backend и обновить приложение для чистой книги/прогресса.
   Нажать вход возле доставки; выбрать «Семья · паста».
2. Открыть «Спагетти болоньезе», сохранить в книгу. В «Повторить» появляется
   сохранённый рецепт; XP за сохранение нет.
3. Выбрать уценку лука в плане: 29,90 ₽ вместо 49,90 ₽. Сохранить план,
   подтвердить demo-чек: 0 XP, 20 ₽ экономии; готовка ещё не завершена.
4. Нажать «Начать готовить»: открывается кухня с шагами. Нажать «Я приготовил»:
   итого 20 XP при свободном лимите дня. Повтор того же чека не меняет награды. При недоступном backend
   готовка остаётся открытой с ошибкой; после восстановления запрос можно повторить.
5. Выбрать это же блюдо заново, переключиться на «Без готовки»: в чеке должен
   оказаться готовый болоньезе, а не лук. Чек завершает ready-сценарий сразу;
   после шага 4 бонус за день уже получен, поэтому дополнительных XP нет.
6. Выбрать «Пасту с томатами»: план без докупок завершается без чека и без
   прибавки к дням покупок. При свободном лимите подтверждённый исходный чек
   даёт 20 XP за **04.09** (итого 40 XP за два покупочных дня): на шаге 4
   использован лимит **05.09**, даты различаются. Второе такое задание по текущему
   чеку уже даёт 0 XP. Это не дополнительная покупка. Чистый HOME
   без подходящего чека завершается с 0 XP, что отдельно проверяется API-тестом.
7. Проверить «У работы» и другую полную точку; «Новое» открывает куриный суп с
   полной корзиной. Смена места сбрасывает прежний выбор товаров.
8. Остановить backend: новая выдача показывает ошибку, не локальный каталог.
   Быстро сменить дом/работу: старый сетевой ответ не должен перезаписать новый.
9. Развернуть и свернуть панель кухни кнопкой и жестом после загрузки/изменения
   размеров окна. Проверить небольшую высоту экрана и прокрутку шагов. В списке
   не пропадают продукты без свободного слота; после готовки упаковки не исчезают.
10. В профиле выбрать «Овощные ужины»: прежние план/готовка исчезают, XP и книга
    другого покупателя загружаются с API. В подборе остаётся паста; мясных блюд нет.
    Выбрать «Домашний суп»: на кухне курица, морковь и лук, основное блюдо — суп.
    Вернуться к семье: её книга и серверные XP сохраняются, текущий план сброшен.
    Повторить смену во время медленного ответа API: поздний результат не должен
    менять нового покупателя. Это пункты для ручного прогона, не отметка о выполнении.

При нескольких сценариях в один synthetic-покупочный день только одно задание
даёт 20 XP; обычная покупка XP не даёт. Demo-часы: 05.09.2026 12:00 МСК.

## Что ещё не готово

- Ручной прогон на телефоне и UI-полировка с автором макетов.
- Проверенные инструкции за пределами трёх рецептов и финальная оценка качества
  ML на отдельной выборке; три переключаемых cooking-примера подключены.
- Пользовательская поправка «закончилось» и количество порций/упаковок.
- Кухня начинается с недавнего чека активного профиля и пополняется покупками
  текущей сессии после принятия сервером. При смене профиля/перезапуске список сбрасывается;
  это не точный остаток, не источник сроков годности и не автоматический ввод HOME в ML.
- Выбор украшения дома; frontend рефералов и приватного ранга.
- Книга живёт до перезапуска backend. Текущий план UI не переживает перезапуск
  приложения; переход к другому блюду не даёт открыть старый план из истории.
- Реальные остатки, актуализация цен на будущий визит, заказ доставки и оплата
  отсутствуют. Нельзя обещать наличие уценки завтра; на экране есть предупреждение.
- Сервер связывает план с собственным оффером и проверенными synthetic-чеками.
  Но нет production-auth, кассовой интеграции и доказательства реальности
  входного чека/каталога: эту границу нельзя считать промышленной защитой.
- Данные синтетические. Никакой измеренный причинный uplift этой сборкой не заявляется.

# Какие API ещё нужны мобильному демо

Frontend использует три существующих endpoint: `POST /api/v1/recommendations`, `POST /api/v1/events/receipts` и `GET /api/v1/progress/{user_id}`. Остальные действия, для которых backend-контракта пока нет, работают локально и не отправляют данные на сервер.

## 1. Состояние кухни

Нужен endpoint, который возвращает актуальный остаток продуктов пользователя по чекам:

```text
GET /api/v1/kitchen/{user_id}
```

Для каждой позиции нужны `ingredient_id`, название, количество и единица, дата покупки, рассчитанный срок годности, остаток дней и источник данных. Сейчас `ReceiptItem` не содержит срока годности, а backend не рассчитывает остатки после использования продукта.

## 2. Полная карточка рецепта

Нужен endpoint:

```text
GET /api/v1/recipes/{recipe_id}
```

В ответе должны быть описание, количество порций, общее время, изображение блюда и этапы приготовления с отдельным временем каждого этапа. Текущий `RecipeRecommendation` содержит только название, ингредиенты и причины рекомендации.

## 3. Ручное изменение наличия ингредиента

Крестик «этого нет» и галочка «это уже есть / куплено в другом магазине» сейчас меняют только локальное состояние приложения. Нужен контракт для сохранения пользовательской поправки, например:

```text
PATCH /api/v1/kitchen/ingredients/{ingredient_id}
```

Поля: `user_id`, `available`, необязательные количество и комментарий к источнику.

## 4. Каталог замен для любого ингредиента

Нужен endpoint:

```text
GET /api/v1/catalog/substitutions?ingredient_id=...&recipe_id=...
```

Он должен возвращать несколько обычных товаров для выбранного ингредиента, включая изображение, цену, фасовку, рейтинг, X5-баллы и доступность. Сейчас `product_options` приходят только внутри рекомендации и только для недостающего ингредиента; медиа, рейтинг и баллы отсутствуют.

## 5. Готовая еда вместо рецепта

Первый блок экрана товаров предлагает готовое блюдо. Для него нужен отдельный источник:

```text
GET /api/v1/recipes/{recipe_id}/ready-meals
```

Нужны SKU, название, изображение, вес, цена, рейтинг и доступность в выбранном магазине.

## 6. Корзина X5

Кнопки «В корзину» и нижняя сумма пока моковые. Для реальной интеграции нужны создание/получение корзины, добавление позиции, изменение количества и удаление позиции. Минимальный контракт для демо:

```text
POST /api/v1/cart/items
GET  /api/v1/cart/{user_id}
```

## Что дорабатывать в существующей рекомендации

- Зафиксировать продуктовую договорённость: frontend не показывает уценку и не использует `markdown`-варианты.
- Добавить в ингредиент требуемое количество и единицу измерения либо ссылку на полную карточку рецепта.
- Добавить стабильные URL изображений рецептов и товаров.
- При необходимости отдавать готовые секции `current`, `repeat`, `explore` с метаданными истории приготовления; сейчас frontend группирует рекомендации по `mode` самостоятельно.

До появления этих контрактов перечисленные данные лежат в `src/data/demo.ts`, а действия не выходят за пределы приложения.

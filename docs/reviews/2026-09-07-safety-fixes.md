# S1–S3: исправления safety-аудита

07.09.2026. База `experiment/vxofi@f5c4795` (то же содержимое, что merge PR #10
`main@54ec3c5`). По запросу vxofi закрыты три находки
[исходного аудита](2026-09-07-poc-system-safety-audit.md); исходные доказательства
не переписаны результатами исправленной версии.

## Изменения

| Находка | Исправление | Что сохраняется |
|---|---|---|
| S1: составной товар обходит исключения | Общая проверка всей упаковки: ID ингредиентов, основная и содержащиеся категории. Исключённая упаковка чека не даёт домашнее покрытие | При наличии безопасной замены рецепт можно предложить с докупкой; подходящий ready остаётся |
| S2: неизвестный ready-состав считается совместимым | Необязательные `composition_complete`/`composition_source`; при исключениях пропускается только полный известный состав производителя или синтетической фикстуры | Без исключений неизвестный состав сам по себе не блокирует ready. Proxy рецепта не превращается в подтверждённый SKU |
| S3: несохраняемая «полная» корзина | Удалён fallback по категории; SKU нескольких обязательных недостающих групп не используется до выбора магазина | Однозначные альтернативы и другой допустимый магазин сохраняются; поздние guards плана/чека/XP не ослаблены |

Исполняемые изменения — `app/contracts.py`, `app/safety.py`, `app/service.py`.
Два ready-SKU mobile и пример омлета помечены `synthetic_fixture`, а не
«проверенный состав X5». [Полный контракт и границы](../catalog-safety.md).
Поля ответа и версия API 1.3 не менялись; старый вход без новых полей допустим,
но при исключениях отсутствие подтверждения теперь скрывает ready.

Не изменены экраны, стили, ассеты, порядок UI, обработчики checkout и наград.
Локальные изменения коллеги в шести `recsys/*` файлах не исправлялись и не
включаются в этот набор изменений. Проверки ниже выполнены в рабочей копии,
где они уже присутствовали, как и в исходном аудите.

## Регрессии и воспроизводимость

В `tests/test_catalog_safety.py` — 606 проверок: 175 направленных сценариев ×
3 движка плюс 81 проверка замены исключённой покупки, полноты/источника состава
и однозначной корзины. Для каждого surviving cook из направленного набора
проверяется **сохранение плана через HTTP**, а не только наличие маршрута.

Два явных уточнения исходного audit harness:

1. Контрольный готовый SKU помечен полным синтетическим составом. Это позволяет
   отличить безопасную контрольную фикстуру от специально неизвестного состава.
2. `excluded_known_receipt_component` ожидает cook **с новой безопасной покупкой**,
   потому что такой SKU есть в inventory. Сам исключённый чек не покрывает
   ингредиент. Отдельные тесты проверяют source/SKU/missing count и отсутствие
   cook, когда безопасной замены нет. Это исправление слишком жёсткого ожидания
   аудита, не разрешение использовать исходную упаковку.

Новый набор отдельно повторён с `PYTHONHASHSEED=1` и `2`: **606/606** в каждом.
При повторе исправлено хрупкое сравнение в новом тесте: `available_routes` —
множество, его JSON-порядок не определяет `default_route`. Код приложения
ради порядка массива не менялся.

```sh
.venv/bin/python -m pytest -o addopts='' -q tests/test_catalog_safety.py
.venv/bin/python -m scripts.poc_system_safety_audit --check \
  --output artifacts/safety-audit-2026-09-07/fixed-directed.json
```

`--check` — новый opt-in: завершает процесс с ошибкой при нарушениях.
Без него прежний режим генерации отчёта сохранён. Направленный набор также
включён в обычный pytest/CI, дополнительной ручной команды для regression gate нет.
Исходный `directed.json` не перезаписан.

с изолированным TestClient и блокировкой внешней сети. Новые JSON/PNG находятся
в `artifacts/safety-audit-2026-09-07/fixed/`; исходный browser-отчёт сохранён.
Cook и потеря ответа проверены TS→API, не новым браузерным сценарием.

## Документация и остаточные ограничения

- [Статус](../project-status.md) и [чеклист](../poc-readiness.md) переписаны
  компактно под PR #10 и safety-fix; прежние тексты сохранены в отдельных историях.
- [Карта документов](../README.md), README, design и handoff ведут на текущие
  контракты. Старые планы merge/UX явно архивные; ответы команды не удалены.
- Синтетическая полнота не подтверждает состав производителя. Свежесть и
  количество дома не устанавливаются по чеку; нет медицинской гарантии.
- Физический телефон, production auth/checkout/возвраты, независимый eval и
  реальный uplift остаются вне доказательств этого исправления.

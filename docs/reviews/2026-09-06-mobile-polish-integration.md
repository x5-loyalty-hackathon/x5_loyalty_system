# Интеграция mobile-polish: визуал не переопределяем

Статус: локальная интеграция проверена; без push в origin/main.
Источник: `feat/mobile-polish` на `3006492` (06.09).

## Решение пользователя

Визуал ветки коллеги — источник истины: ассеты, геометрия, положение кнопок,
состав и порядок экранов, переходы. Изменения этих вещей требуют отдельного
согласования с vxofi. Системные правила покупки, наград, безопасности и
изоляции состояния остаются нашими; перенос интерфейса не отменяет их.

## План

1. Сохранить локальную реализацию отдельным checkpoint-коммитом, не добавляя
   пользовательские исследовательские черновики. Это страховка перед merge,
   не утверждение нашего прежнего визуала и не публикация в main.
2. Влить зафиксированный `3006492`: сохранить его экраны и ассеты, включая
   «Мой план» из кухни и переход к готовке из карточки при отсутствии докупок.
3. При сведении `DemoContext` сохранить серверный plan/offer, проверку покупки,
   запрет пассивного XP, повторы запросов и изоляцию сессий покупателей.
4. Согласовать пересечения оформления: уровни каталога и отсутствие прежних
   элементов выбора цели/demo-покупателя. Не дорисовывать элементы молча.
5. Проверить клиентские тесты, typecheck, API с mock/model, backend и экспорт.
   Отдельно проверить браузерные сценарии и неизменность согласованных файлов
   интерфейса относительно источника; тест API не заменяет проверку экрана.
6. Обновить статус, контракт и инструкции передачи. `main` и новую ML-ветку
   не включать в этот merge автоматически.

## Пересечения, ожидающие ответа

- У коллеги десять предметов на уровнях 2, 4, …, 20. У нас были обои на уровнях
  2–4. Ассеты берём его, конкретные пороги пока не выбираем за пользователя.
- В его экранах нет нашего переключателя demo-покупателей и выбора будущей
  награды. Запрошено подтверждение: сохранить его интерфейс без добавлений
  либо отдельно предложить и согласовать расположение.
- Его выбор установленных предметов пока локальный. Серверный уровень — не
  то же самое, что серверная проверка и сохранение применённого предмета;
  механическую интеграцию надо проверять отдельно от визуала.

Пока ответа нет, исходный каталог/пороги и экраны коллеги сохранены без
изменений. Это не объявляет баланс отдельно согласованным. Прежние UI-компоненты
и API обоев сохранены, но не используются новыми экранами. Не считать C6 полностью
закрытым: его серверное сохранение не управляет десятью новыми предметами.

  не включены. Конфликты `index.tsx`, `KitchenScene.tsx` решены точным переносом
  версии коллеги; его же вариант `profile.tsx` и `recipes.tsx` сохранён без
  наших дополнительных кнопок. Ни один исходный экран не добавлен/удалён.
- В `DemoContext` соединены `persistPlan/savePlanAndCook` с активным user_id и
  поколением сессии. Поздний ответ A после A → B → A не открывает готовку;
  потеря ответа повторяет тот же plan_id и payload, а не выдаёт новый план.
  Локальное оформление очищается при переключении профиля, не переходит к другому.
- Полный Python-прогон checkpoint: **546 passed / 3 skipped**; после него
  backend/ML/Python-тесты в этом merge не менялись.

  повтор и смену профиля в короткой готовке. **14 API на mock + 14 на model**,
  fallback запрещён. HOME без подтверждённой покупки: готовка без чека и 0 XP.
- TypeScript и Expo export **web/iOS/Android** — успешно. Первый export упёрся
  в запись telemetry вне sandbox; повтор с `EXPO_NO_TELEMETRY=1` прошёл без
  изменения домашнего каталога и правил приложения.
- Guard проверяет **71 исходный файл**: экраны, компоненты, данные геометрии,
  тему и ассеты относительно `3006492`. Слои кухни: `changed bytes: 0`.

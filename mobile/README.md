# Мобильное демо «X5 Домовой»

React Native + Expo Go. Четыре экрана из дизайн-макета, работающие на живом
FastAPI из этого же репозитория. План — [docs/frontend-demo-plan.md](../docs/frontend-demo-plan.md).

## Запуск

1. Backend (из корня репозитория):

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

2. Узнать адрес Mac и положить его в `mobile/.env`:

```bash
ipconfig getifaddr en0
```

```text
EXPO_PUBLIC_API_BASE_URL=http://<адрес>:8000
```

`.env` не коммитится — образец лежит в `.env.example`. `localhost` не подходит:
для приложения на iPhone это сам iPhone.

3. Приложение:

```bash
npm install --legacy-peer-deps
npx expo start
```

Отсканировать QR камерой iPhone и открыть в Expo Go. Для быстрой проверки
вёрстки на Mac есть веб-версия: `npx expo start --web`.

## Экраны

| Маршрут | Экран | Данные |
|---|---|---|
| `/` | Кухня Домового: XP, уровень, экономия, rescue-позиции, приватный ранг | `GET /api/v1/progress/{user_id}` |
| `/recipes` | Что приготовить: `Из корзины / Повторить / Новые` | `POST /api/v1/recommendations` |
| `/recipe` | Рецепт: ингредиенты с переключением статуса, этапы | выбранная рекомендация |
| `/products` | Товары: готовое блюдо и замены, корзина | локальный каталог + отправка чека |

Подтверждение покупки шлёт `POST /api/v1/events/receipts` и возвращает на первый
экран с обновлённым прогрессом.

## Как устроены данные

`src/data/demo.ts` держит демо-каталог рецептов, товаров и этапов приготовления —
всего этого нет в контракте v1. Живой ответ рекомендаций накладывается поверх
него в `mergeRecommendation`: id, название, режим и состав ингредиентов берутся
из API, а время, порции, описание и этапы — из локального контента.

Если backend недоступен, экран рецептов честно переключается на демо-данные и
пишет об этом в подсказке Домового. Экран прогресса в этом случае показывает
ошибку и кнопку «Повторить» — прогресс не выдумывается.

## Что осознанно не реализовано

- **Уценка не выводится в интерфейсе.** Backend умеет `markdown` и отдаёт
  предупреждение «товар не забронирован», но по продуктовому решению команды
  демо показывает сначала готовое блюдо, затем обычные замены.
- Реферальная механика: реализована в backend, экрана нет.
- Фотографии блюд и товаров — штрихованные плейсхолдеры, как в макете.
- Рейтинги товаров, «24 товара», «готовили 9 раз» — демо-контент.

## Заметки для демонстрации

- Повторная отправка того же чека возвращает `duplicate` — это идемпотентность,
  а не ошибка. Прогресс при этом приходит актуальный, поэтому прогон можно
  повторять без перезапуска backend.
- Кухня нарисована пиксель в пиксель по `kitchen-art.js` из дизайн-бандла:
  сетка 117×156, в приложении показан верхний срез 117×62.
- CORS backend открыт для `localhost:8081` только ради веб-версии Expo.
  Expo Go на устройстве CORS не проверяет.
